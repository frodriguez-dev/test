# Frontend

React single-page application, initialized with React, TypeScript, Vite, and
pnpm in issue #18, with Tailwind CSS and shadcn/ui as the visual system (issue
#20). Session authentication in issue #24 added routing and the login screen.

## Getting started

Requires Node.js 20.19 or higher and pnpm.

```bash
cd frontend
pnpm install
pnpm dev          # start the Vite dev server
pnpm build        # type-check and build for production
pnpm preview      # serve the production build locally
pnpm generate:api # regenerate TypeScript types from the OpenAPI contract
pnpm check        # type-check, lint, format check, and tests
```

### Docker Compose

From the repository root, `docker compose up --build` starts the frontend with
the backend and PostgreSQL. The source directory is bind-mounted and Vite serves
the app on <http://localhost:5173> with hot module replacement; dependencies
stay in a named volume so the container does not depend on a host
`node_modules/`. See the root
[`README.md`](../README.md#local-development-with-docker-compose) for the full
workflow.

## Structure

```
frontend/
├── public/                 # Static assets served as-is
├── src/
│   ├── api/                # HTTP client and endpoint modules (backend boundary)
│   ├── assets/             # Imported images, fonts, and other bundled assets
│   ├── components/         # Reusable, presentation-focused UI components
│   │   └── ui/             # shadcn/ui components generated by its CLI
│   ├── features/           # Vertical slices: components, hooks, and state per domain
│   │   └── auth/           # Session state, login form, and route guard
│   ├── hooks/              # Shared React hooks not tied to one feature
│   ├── lib/                # Framework-agnostic helpers (formatting, validation)
│   ├── pages/              # Route-level screens that compose features
│   │   ├── HomePage.tsx    # Protected example route
│   │   └── LoginPage.tsx   # Public login screen
│   ├── styles/             # Global styles, design tokens, and theme setup
│   ├── test/               # Vitest setup shared by every test file
│   ├── types/              # Shared TypeScript types
│   │   └── api/            # Generated from docs/api/openapi.yaml; do not edit
│   ├── App.tsx             # Route composition
│   └── main.tsx            # Application entry point
├── components.json         # shadcn/ui configuration
├── eslint.config.js        # ESLint flat configuration
├── .prettierrc.json        # Prettier formatting rules
├── index.html
├── package.json
├── pnpm-lock.yaml
├── tsconfig.json
└── vite.config.ts
```

Only create the directories that are actually needed. The tree describes where
code belongs, not a checklist of empty folders.

## Import alias

`@/*` resolves to `src/*`, configured in both `tsconfig.app.json` (`paths`) and
`vite.config.ts` (`resolve.alias`). Prefer the alias over long relative paths.

```ts
import { HomePage } from '@/pages/HomePage'
```

## API communication

- During development the Vite dev server proxies every `/api` request to Django
  (default `http://localhost:8000`). Configure the target with
  `VITE_API_PROXY_TARGET`; Docker Compose sets it to `http://backend:8000`.
  Copy `.env.example` to `.env` only if you need a different target.
- API calls run through `src/api/client.ts`, which centralizes `fetch`, response
  parsing, CSRF headers, and errors (`ApiError`). Endpoint modules such as
  `src/api/health.ts` and `src/api/auth.ts` use that client and return generated
  types; UI components never call `fetch` directly.
- `src/types/api/` is generated from the committed contract at
  `docs/api/openapi.yaml` with
  [openapi-typescript-codegen](https://github.com/hey-api/openapi-typescript-codegen).
  Do not edit those files by hand; the contract is the source of truth.

### Regenerating the API types

Whenever a backend endpoint, serializer, or response changes, regenerate the
contract and the TypeScript types in this order:

```bash
# 1. Regenerate the committed OpenAPI contract from the Django code.
cd backend
uv run --env-file .env manage.py spectacular --file ../docs/api/openapi.yaml

# 2. Regenerate the TypeScript types from that contract.
cd ../frontend
pnpm generate:api
```

Commit `docs/api/openapi.yaml` and the changed files under
`frontend/src/types/api/` together with the backend change. The backend test
suite fails when the committed contract is stale.

## Authentication

- `src/features/auth/` owns the session state. `AuthProvider` loads
  `GET /api/v1/auth/me/` on start and exposes `login`, `logout`, and the current
  state through `useAuth`.
- `RequireAuth` guards protected routes. `/` is the protected example route and
  `/login` is public; anonymous visitors are sent to `/login` and returned to
  the requested route after signing in.
- `src/api/client.ts` reads Django's CSRF cookie and sends the token in the
  `X-CSRFToken` header on unsafe requests. It requests a token from
  `/api/v1/auth/csrf/` when the cookie is missing.
- The session is stored in an `HttpOnly` cookie set by the backend. Never store
  credentials or session tokens in `localStorage` or application state.

## Styling

- Tailwind CSS v4 is enabled through the `@tailwindcss/vite` plugin and imported
  from `src/styles/global.css`. Write utility classes in components; avoid
  hand-written component CSS.
- shadcn/ui is configured in `components.json` with the `@/components/ui` alias.
  Its theme tokens live in `src/styles/global.css`, and `src/lib/utils.ts`
  exposes the `cn` class-name helper.
- Add components with the official CLI instead of copying code by hand. Reuse
  the generated components and do not modify them unless a real need appears.

  ```bash
  pnpm dlx shadcn@latest add <component>
  ```

- Do not add another UI library or a custom design system until a later issue
  decides one. shadcn/ui primitives and the generated components are the
  exception because they ship with the CLI.

## Testing and quality

- **Tests.** Vitest runs in a jsdom environment with React Testing Library. Test
  files are colocated with their code as `*.test.ts` or `*.test.tsx`, and
  `src/test/setup.ts` registers the jest-dom matchers and cleanup. Run the suite
  once with `pnpm test` or in watch mode with `pnpm test:watch`.
- **Linting.** ESLint uses the flat configuration in `eslint.config.js` with the
  TypeScript, React Hooks, and React Refresh rules. Generated files under
  `src/types/api/` and shadcn/ui components are excluded from the rules that do
  not apply to generated code.
- **Formatting.** Prettier is the single formatter; `pnpm format` writes changes
  and `pnpm format:check` verifies them. Generated API types, UI primitives, and
  lock files are ignored in `.prettierignore`.
- **Type checks.** `pnpm typecheck` runs `tsc -b` over the application and Node
  configurations without emitting files.

`pnpm check` runs all four checks in sequence and is the command to use before
opening a Pull Request. Keep tests focused on behavior that can regress; do not
add assertions that only restate the implementation.

## Ownership and boundaries

- `src/api/` is the only place that performs HTTP calls. UI code consumes its
  functions instead of calling `fetch` directly.
- `src/pages/` composes `src/features/` and shared `src/components/`; features
  do not import pages.
- `src/features/<domain>/` owns domain-specific state and UI. Other features
  must use its public entry point rather than reaching into internal files.
- `src/lib/` and `src/components/` must not import from `src/features/` or
  `src/pages/`.
- Dependencies flow downward: `pages → features → components/lib → types`.
  Avoid circular imports.
- Backend access happens only through the versioned REST API, never through
  files shared with `backend/`.

## Conventions

- TypeScript runs in strict mode; avoid `any` without a documented reason.
- Name files by their primary export (`UserCard.tsx`, `useCurrentUser.ts`).
- Keep components small and colocate styles, tests, and hooks with their feature
  when they are not shared.
- Add a dependency only with a clear use case; prefer platform APIs and existing
  packages. Commit `pnpm-lock.yaml` with every dependency change.
- Configuration comes from environment variables exposed by Vite
  (`import.meta.env`). Never commit secrets; only public values belong in the
  frontend bundle.

See [`docs/ai/conventions.md`](../docs/ai/conventions.md) for repository-wide
rules and [`docs/decisions.md`](../docs/decisions.md) for the rationale.
